## `defineTool()`

```ts
function defineTool<
  TArgs = unknown,
  TResult = unknown,
  const TName extends string = string,
>(
  tool: ToolDefinition<TArgs, TResult, TName>,
): ToolDefinition<TArgs, TResult, TName>
```

原樣回傳 definition，同時保留 TypeScript generics 與 literal `name` type。

```ts
const updateCounter = defineTool<
  { delta: number },
  { value: number }
>({
  name: "update_counter",
  description: "Update the visible counter by delta.",
  argsSchema: {
    type: "object",
    properties: {
      delta: { type: "integer" },
    },
    required: ["delta"],
  },
  handler: ({ delta }) => ({ value: counter.add(delta) }),
});
```

`defineTool()` 本身不做 validation；session creation 會 normalize/validate tools。

## `defineDenoModule()`

Vite 應用可以用預定的 `skills.denoModules` authoring shape 描述 local 或 package-backed Deno module：

```ts
import { defineDenoModule } from "@kaoruisaac/pedelec";

const spriteTools = defineDenoModule({
  name: "sprite-tools",
  description: "Sprite authoring and preview utilities.",
  entry: "./agent/sprite-tools.ts",
  usage: `import { previewActorSource } from "sprite-tools";`,
});

const skills = {
  guidance: "Use the module when sprite preview is needed.",
  tools: [],
  denoModules: [spriteTools],
};
```

此階段只涵蓋 build-time authoring。`defineDenoModule()` 保留靜態描述；`pedelecVitePlugin()` 會在 `vite build` 與 `vite dev` 解析 `entry`、打包 self-contained ESM runtime，並 roll-up 獨立的 public declaration artifact。Session transport、Core materialization、Deno import mapping 與 execution 都尚未實作。把 `denoModules` 傳進 `createSession()` 不會載入或執行該 module。

只使用 root SDK、從不 import `@kaoruisaac/pedelec/vite` 的應用不需要 Vite；Vite peer 是 optional。使用 plugin 的應用必須安裝支援的 Vite 8：

```bash
npm install @kaoruisaac/pedelec vite
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { pedelecVitePlugin } from "@kaoruisaac/pedelec/vite";

export default defineConfig({
  plugins: [pedelecVitePlugin()],
});
```

`entry` 必須是靜態字串。相對路徑從宣告所在 source file 解析。Vite string alias 與已安裝 package specifier（含 `package.json` `exports` subpath）會走應用程式的 Vite resolver（runtime）與 TypeScript bundler resolution（public types）。Remote URL、computed value、inline source 與 imported module object 都不支援。

Plugin 會在轉換後的 module object 上附加 private、non-enumerable 的 runtime/types artifact，並移除原始 authoring `entry` path。它不會寫入應用程式的 Pedelec workspace，也不會 mutate 既有 session。

`usage` 請保持精簡：它是常見情境的 agent hint；需要檢查 enum 或 option shape 時，以 generated declaration bundle 為準。

## `ToolDefinition`

```ts
type ToolDefinition<
  TArgs = unknown,
  TResult = unknown,
  TName extends string = string,
> = {
  name: TName;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
  handler?: ToolSpecificHandler<TArgs, TResult>;
};
```

| Field | Required | 說明 |
| --- | --- | --- |
| `name` | Yes | Agent-facing name；letter 開頭，只能包含 letter、digit、`_`、`.`、`-`。 |
| `description` | Yes | Non-empty 行為、side effect 與選擇條件說明。 |
| `argsSchema` | Yes | Pedelec Tool Args Schema；root 必須 object。 |
| `timeoutMs` | No | Positive integer runtime wait limit；Core 目前預設 60 秒。 |
| `handler` | No | SDK 保存在 browser、不送到 Core 的 inline handler。 |

同一 skills manifest 的 names 必須 unique。

## `ToolSpecificHandler`

```ts
type ToolSpecificHandler<TArgs = unknown, TResult = unknown> = (
  args: TArgs,
  ctx: ToolCallContext,
) => TResult | Promise<TResult>;
```

Handler 在 browser page context 執行。Type parameters 只有 compile-time，runtime args 仍要 validate。

Return value 必須符合 bridge JSON data model。

## `SkillsInput`

```ts
type SkillsInput<
  TTools extends readonly ToolDefinition[] = readonly ToolDefinition[],
> = {
  guidance: string;
  tools: TTools;
  denoModules?: readonly DenoModuleDefinition[];
};
```

```ts
const tools = [getCurrentPage, updateCounter] as const;

const skills = {
  guidance: "Read current state before making changes.",
  tools,
} satisfies SkillsInput<typeof tools>;
```

`guidance` 必須 string，`tools` 必須 array。`denoModules` 是 Vite-prepared Deno modules 的預定 authoring list；此階段不會 transport 或執行它們。

## `ToolNameOf`

```ts
type ToolNameOf<TTools extends readonly ToolDefinition[]> = Extract<
  TTools[number]["name"],
  string
>;
```

從 readonly definitions array 取出 tool name union。

```ts
const tools = [readPage, updateCounter] as const;
type AppToolName = ToolNameOf<typeof tools>;
// "get_current_page" | "update_counter"
```

`createSession()` 用它收窄 named `session.onTool()`。

## `SerializableToolManifest`

```ts
type SerializableToolManifest = {
  name: string;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
};
```

送到 Core 的 tool shape，刻意不包含 `handler`。

## `SerializableSkillsManifest`

```ts
type SerializableSkillsManifest = {
  guidance: string;
  tools: SerializableToolManifest[];
};
```

經 normalize 後送進 bridge 的 skills payload。

## Inline handler normalization

`createSession()` 期間：

1. 檢查 tool entries；
2. 透過 JSON serialization clone `argsSchema`；
3. 依 name 將 inline handlers 保存在 browser-side map；
4. 將 serializable definitions 送到 Core。

Duplicate tool name reject `INVALID_INPUT`。

Legacy `input` shorthand 已不支援，請使用 `argsSchema`。

## Handler resolution

Incoming tool call 依序：

1. session named handler；
2. original definition inline handler；
3. generic fallback；
4. SDK-created `TOOL_HANDLER_NOT_FOUND` result。

Handler exception 變成 `TOOL_HANDLER_ERROR` result；delivery failure emit `SUBMIT_TOOL_RESULT_FAILED`。

## Tool Args Schema entry types

Root alias：

```ts
type ToolArgsSchema = ToolArgsObjectSchema;
```

Node union：

```ts
type ToolArgsSchemaNode =
  | ToolArgsStringSchema
  | ToolArgsNumberSchema
  | ToolArgsIntegerSchema
  | ToolArgsBooleanSchema
  | ToolArgsArraySchema
  | ToolArgsObjectSchema
  | ToolArgsOneOfSchema;
```

所有欄位見 [Types](./types/)，使用方式見 [Tool Args Schema](../tools/args-schema/)。
