## `defineTool()`

```ts
function defineTool<
  TArgs = unknown,
  TResult = unknown,
  const TName extends string = string,
>(
  tool: ToolDefinition<TArgs, TResult, TName>,
): ToolDefinition<TArgs, TResult, TName>
```

原樣回傳 definition，同時保留 TypeScript generics 與 literal `name` type。

```ts
const updateCounter = defineTool<
  { delta: number },
  { value: number }
>({
  name: "update_counter",
  description: "Update the visible counter by delta.",
  argsSchema: {
    type: "object",
    properties: {
      delta: { type: "integer" },
    },
    required: ["delta"],
  },
  handler: ({ delta }) => ({ value: counter.add(delta) }),
});
```

`defineTool()` 本身不做 validation；session creation 會 normalize/validate tools。

## `defineDenoModule()`

Vite 應用使用同一個 authoring shape 描述 local 或 package-backed Deno module。Minimal declaration 可以給 `workspace.run()` 使用：

```ts
import { defineDenoModule } from "@kaoruisaac/pedelec";

const sceneTools = defineDenoModule({
  name: "scene-tools",
  entry: "./deno/scene-tools.ts",
});

const result = await workspace.run(
  `import { buildScene } from "scene-tools";\nawait buildScene();`,
  { denoModules: [sceneTools] },
);
```

同一個 declaration 若也要給 `skills.denoModules` 使用，可以加入 Agent metadata：

```ts
import { defineDenoModule } from "@kaoruisaac/pedelec";

const spriteTools = defineDenoModule({
  name: "sprite-tools",
  description: "Sprite authoring and preview utilities.",
  entry: "./agent/sprite-tools.ts",
  usage: `import { previewActorSource } from "sprite-tools";`,
  preferStdinExecution: true,
});

const skills = {
  guidance: "Use the module when sprite preview is needed.",
  tools: [],
  denoModules: [spriteTools],
};
```

`defineDenoModule()` 保留 concrete declaration shape，包括 optional metadata 是否真的有提供。`pedelecVitePlugin()` 會在 `vite build` 與 `vite dev` 解析 `entry`、打包 self-contained ESM runtime，並 roll-up 獨立的 public declaration artifact。`createSession()` 會自動傳送 prepared artifact，Core 在 session 回傳前建立 immutable、thread-scoped package 與 import map。`workspace.run()` 使用同一種 prepared artifact format，但會按 Workspace 與 authorized SDK origin cache packages，再為每次 run 只對 requested names 建立 exact import map。

只使用 root SDK、從不 import `@kaoruisaac/pedelec/vite` 的應用不需要 Vite；Vite peer 是 optional。使用 plugin 的應用必須安裝支援的 Vite 8：

```bash
npm install @kaoruisaac/pedelec vite
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { pedelecVitePlugin } from "@kaoruisaac/pedelec/vite";

export default defineConfig({
  plugins: [pedelecVitePlugin()],
});
```

`entry` 必須是靜態字串。相對路徑從宣告所在 source file 解析。Vite string alias 與已安裝 package specifier（含 `package.json` `exports` subpath）會走應用程式的 Vite resolver（runtime）與 TypeScript bundler resolution（public types）。Remote URL、computed value、inline source 與 imported module object 都不支援。

Plugin 會在轉換後的 module object 上附加 private、non-enumerable 的 runtime/types artifact，並移除原始 authoring `entry` path。它不會寫入應用程式的 Pedelec workspace，也不會 mutate 既有 session。

`usage` 請保持精簡：它是常見情境的 agent hint；需要檢查 enum 或 option shape 時，以 generated declaration bundle 為準。

Agent 會在以 `pedelec-deno` 執行的 JavaScript/TypeScript script 中，以 logical `name` import module，不會以 private filesystem path 執行 module。Host Context 會列出 name、description、usage，以及 workspace-relative 的 `index.d.ts` pointer，供精確 API discovery；generated `index.mjs` 是 implementation fallback，不是一般 API reference。

`preferStdinExecution` 是主要用於短 script 的 optional boolean preference。設為 `true` 時，Host Context 會加入 module-specific `runCommandTemplate`，例如 `@'\n<typescript-source>\n'@ | pedelec-deno --thread-id <thread-id> run -`，讓 Agent 只需要替換 TypeScript source placeholder，不必自行決定如何序列化 stdin；raw preference flag 不會暴露在 Agent-facing object。這不是限制，file-backed execution 仍然有效；省略或設為 `false` 會維持預設行為，也不會影響 bundling 或 artifact contents。

`entry` 支援 local relative file、Vite alias，以及已安裝的 bare/package `exports` specifier。它只在 build-time 使用；Desktop 不會解析它，runtime 也不能 fetch npm、JSR 或 network。Imported module 和 Agent script 共用相同受限制的 Pedelec Deno permissions。

只要 Core 仍知道該 thread，end/resume 會保留同一份 module snapshot。`pedelec.resumeSession(sessionId)` 會重新 attach 到既有 snapshot；要使用重建後的 artifact，請建立新 session。`skills.tools` 是分開的 App Tool capability：呼叫走 `pedelec-cli --thread-id ... tool-spec` 與 `tool-call`，Deno Modules 則留在 `pedelec-deno` script 內。

## `ToolDefinition`

```ts
type ToolDefinition<
  TArgs = unknown,
  TResult = unknown,
  TName extends string = string,
> = {
  name: TName;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
  handler?: ToolSpecificHandler<TArgs, TResult>;
};
```

| Field | Required | 說明 |
| --- | --- | --- |
| `name` | Yes | Agent-facing name；letter 開頭，只能包含 letter、digit、`_`、`.`、`-`。 |
| `description` | Yes | Non-empty 行為、side effect 與選擇條件說明。 |
| `argsSchema` | Yes | Pedelec Tool Args Schema；root 必須 object。 |
| `timeoutMs` | No | Positive integer runtime wait limit；Core 目前預設 60 秒。 |
| `handler` | No | SDK 保存在 browser、不送到 Core 的 inline handler。 |

同一 skills manifest 的 names 必須 unique。

## `ToolSpecificHandler`

```ts
type ToolSpecificHandler<TArgs = unknown, TResult = unknown> = (
  args: TArgs,
  ctx: ToolCallContext,
) => TResult | Promise<TResult>;
```

Handler 在 browser page context 執行。Type parameters 只有 compile-time，runtime args 仍要 validate。

Return value 必須符合 bridge JSON data model。

## `SkillsInput`

```ts
type AgentDenoModuleDefinition<TName extends string = string> =
  DenoModuleDefinition<TName> & {
    description: string;
    usage: string;
  };

type SkillsInput<
  TTools extends readonly ToolDefinition[] = readonly ToolDefinition[],
> = {
  guidance: string;
  tools: TTools;
  denoModules?: readonly AgentDenoModuleDefinition[];
};
```

```ts
const tools = [getCurrentPage, updateCounter] as const;

const skills = {
  guidance: "Read current state before making changes.",
  tools,
} satisfies SkillsInput<typeof tools>;
```

`guidance` 必須是 string，`tools` 必須是 array。`denoModules` 是 optional；Session/Agent modules 需要 `name`、`description`、`entry`、`usage`，且 Agent metadata 必須是 non-empty。Workspace-only 的 `workspace.run()` declaration 只需要 `name`、`entry` 與 prepared Vite artifact。`preferStdinExecution` 是 optional boolean preference，對 Workspace execution 沒有作用。Session artifacts 會在 `createSession()` transport；Workspace artifacts 在需要時準備，並在 Core runtime cache 有效期間重用。

## `ToolNameOf`

```ts
type ToolNameOf<TTools extends readonly ToolDefinition[]> = Extract<
  TTools[number]["name"],
  string
>;
```

從 readonly definitions array 取出 tool name union。

```ts
const tools = [readPage, updateCounter] as const;
type AppToolName = ToolNameOf<typeof tools>;
// "get_current_page" | "update_counter"
```

`createSession()` 用它收窄 named `session.onTool()`。

## `SerializableToolManifest`

```ts
type SerializableToolManifest = {
  name: string;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
};
```

送到 Core 的 tool shape，刻意不包含 `handler`。

## `SerializableSkillsManifest`

```ts
type SerializableSkillsManifest = {
  guidance: string;
  tools: SerializableToolManifest[];
  denoModules?: Array<{
    name: string;
    description: string;
    usage: string;
    preferStdinExecution?: boolean;
  }>;
};
```

經 normalize 後送進 bridge 的 skills metadata。Prepared runtime 與 declaration source 會走內部 session setup path 傳送；`entry` 不會送到 Core。

## Inline handler normalization

`createSession()` 期間：

1. 檢查 tool entries；
2. 透過 JSON serialization clone `argsSchema`；
3. 依 name 將 inline handlers 保存在 browser-side map；
4. 將 serializable definitions 送到 Core。

Duplicate tool name reject `INVALID_INPUT`。

Legacy `input` shorthand 已不支援，請使用 `argsSchema`。

## Handler resolution

Incoming tool call 依序：

1. session named handler；
2. original definition inline handler；
3. generic fallback；
4. SDK-created `TOOL_HANDLER_NOT_FOUND` result。

Handler exception 變成 `TOOL_HANDLER_ERROR` result；delivery failure emit `SUBMIT_TOOL_RESULT_FAILED`。

## Tool Args Schema entry types

Root alias：

```ts
type ToolArgsSchema = ToolArgsObjectSchema;
```

Node union：

```ts
type ToolArgsSchemaNode =
  | ToolArgsStringSchema
  | ToolArgsNumberSchema
  | ToolArgsIntegerSchema
  | ToolArgsBooleanSchema
  | ToolArgsArraySchema
  | ToolArgsObjectSchema
  | ToolArgsOneOfSchema;
```
