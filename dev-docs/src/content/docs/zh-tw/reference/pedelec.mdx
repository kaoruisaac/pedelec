`Pedelec` 是 browser client，擁有 Chrome Extension bridge，並建立或 resume `PedelecSession`。

```ts
import { Pedelec } from "@kaoruisaac/pedelec";
```

## Constructor

```ts
new Pedelec(options?: PedelecOptions)
```

```ts
type PedelecOptions = {
  bridgeTimeoutMs?: number;
};
```

### Parameters

| Parameter | Type | Default | 說明 |
| --- | --- | --- | --- |
| `options.bridgeTimeoutMs` | `number` | `30_000` | 等待 Extension bridge response 的最長時間；小於 1 會 clamp 成 1。 |

Constructor 會立即嘗試連到 Pedelec Chrome Extension。只能在 hydration 後的 browser page 建立。

```ts
const pedelec = new Pedelec({
  bridgeTimeoutMs: 30_000,
});
```

## `createSession()`

```ts
createSession(): Promise<PedelecSession<string>>;

createSession<const TTools extends readonly ToolDefinition[]>(
  input: CreateSessionInput<TTools>,
): Promise<PedelecSession<ToolNameOf<TTools>>>;
```

建立新 Core session，並讓目前 SDK channel subscribe。

### Input

```ts
type CreateSessionInput<TTools extends readonly ToolDefinition[]> =
  | {
      provider: ProviderCode;
      model?: string;
      effortLevel?: "default" | "low" | "high";
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    }
  | {
      provider?: undefined;
      model?: string;
      effortLevel?: "default" | "low" | "high";
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    };
```

### Resolution rules

- 無 `provider`：使用 Desktop `defaultProvider` 並確認 available。
- `provider` 可搭配 provider-independent `effortLevel`；省略時使用 `default`。
- `model` 代表 explicit mode，可搭配 optional provider-native `effort`，不可和 `effortLevel` 共存；profile mode 的完整 model/native effort 仍由 Desktop profile 提供。
- `autoEndOnDisconnect`：預設 `true`。

`createSession()` 一律使用 managed convenience flow，不接受 Workspace configuration。若要使用 application 管理的 Workspace，請呼叫 `openWorkspace()`，再用 `workspace.createSession()`。Workspace methods、lifecycle、concurrency 與 security boundary 請見 [PedelecWorkspace reference](../pedelec-workspace/)。

### Returns

註冊於此 client 的 `PedelecSession`。

### 常見 errors

- approval/transport errors；
- `DEFAULT_PROVIDER_NOT_SET`；
- `DEFAULT_PROVIDER_UNAVAILABLE`；
- `INVALID_INPUT`；
- Ollama profile 沒有 model 時的 `MODEL_REQUIRED`；explicit `{ model }` mode 不需要 profile model；
- provider/Core creation errors。

```ts
const session = await pedelec.createSession({
  provider: "codex",
  autoEndOnDisconnect: true,
});
```

## `openWorkspace()`

```ts
openWorkspace(): Promise<PedelecWorkspace | null>
openWorkspace(path: string): Promise<PedelecWorkspace>
```

開啟或初始化 workspace capability。省略 path 時，Pedelec Desktop 開啟原生資料夾 picker，取消時回傳 `null`；指定 path 時不會開啟 picker。回傳的 workspace 提供 `path`、`createSession()`、`listFiles()`、`listFolders()` 與 `run()`。

```ts
const workspace = await pedelec.openWorkspace();
if (!workspace) return;

const session = await workspace.createSession({ provider: "codex" });
const files = await workspace.listFiles();
const result = await workspace.run("console.log('hello');");
```

這是敏感的 Desktop API，可能觸發目前 origin 的 approval flow。Workspace validation、runtime initialization 與 marker handling 由 Core 負責。不帶 path 的 picker overload 在原生 picker 開啟時不套用一般 SDK bridge timeout；explicit-path overload 會套用設定的 bridge timeout。Extension disconnect 或明確 bridge error 仍會 reject。

## `listProviders()`

```ts
listProviders(): Promise<ProviderInfo[]>
```

取得 Desktop Core 的 provider discovery result。

```ts
type ProviderInfo = {
  name: string;
  code: ProviderCode;
  available: boolean;
  isDefault: boolean;
  error: string | null;
};
```

```ts
const providers = await pedelec.listProviders();
const ready = providers.filter((provider) => provider.available);
```

`isDefault` 表示目前 Desktop settings 選擇的 default provider，與 `available` 無關；即使 default provider unavailable，仍會是 `true`。`available` 是 discovery/setup signal，不保證所有 model 或 remote service ready。為了 forward compatibility，SDK 會忽略 Extension response 中新增的未知欄位。

常見 errors 為 Extension、native host、Core IPC 與 bridge timeout。

## `getSettings()`

```ts
getSettings(): Promise<PedelecSettings>
```

讀取 SDK 可見的 Desktop defaults。

```ts
type PedelecSettings = {
  defaultProvider: ProviderCode | null;
};
```

SDK 會驗證 response shape；不相容時 reject `SDK_PROTOCOL_ERROR`。

```ts
const settings = await pedelec.getSettings();
console.log(settings.defaultProvider);
```

## `getApprovalStatus()`

```ts
getApprovalStatus(): Promise<ApprovalStatus>
```

```ts
type ApprovalStatus = {
  installed: boolean;
  approved: boolean;
  origin: string | null;
  appConnected: boolean;
};
```

讀取目前 origin 的 Extension approval state。

特殊行為：Extension unavailable/disconnected 時 resolve，不 throw：

```ts
{
  installed: false,
  approved: false,
  origin: location.origin,
  appConnected: false
}
```

Protocol/storage 等其他 error 仍可能 reject。

這個 method 不會打開 approval popup；需要時由 `createSession()` 或 `resumeSession()` 觸發。

## `checkAvailability()`

```ts
checkAvailability(): Promise<PedelecAvailability>
```

檢查 Extension、目前 origin 的 approval 與 Desktop readiness；不會建立或 resume session，也不會開啟 approval popup。`getApprovalStatus().appConnected` 是非敏感 Core ping 的連線結果，不代表 approval 或 provider ready。`getSettings()` 與 `listProviders()` 需要 origin approval 並可能開啟 popup，且僅分別公開 defaults 與 `name`/`code`/`available`/`isDefault`/`error`。

`launchAttempted: true` 只代表已送出 settings probe，不能證明 Desktop 已啟動；settings response shape 不合法也會被視為 Desktop unavailable。Extension unavailable 也可能只是 bridge 中斷。

## `resumeSession()`

```ts
resumeSession(sessionId: string): Promise<PedelecSession<string>>
```

讓此 SDK client 以新的 handle subscribe 到既有 Core session，並 hydrate 其 associated `workspace`。這是 reattachment，不會把 `Ended` thread 重新啟用；回傳的 Session 已經包含 `session.workspace`，不需要另外呼叫 `openWorkspace()`。若要在 `end()` 後繼續使用同一個 handle，請改用 `session.resume()`。

```ts
const session = await pedelec.resumeSession(savedSessionId);
```

| Parameter | Type | 說明 |
| --- | --- | --- |
| `sessionId` | `string` | Non-empty Core session/thread identifier。 |

回傳註冊於此 client 的 session handle，並 hydrate 其 owning `workspace`。若 Core session 已是 `Ended`，這個 handle 會維持 `ended`，直到明確呼叫 `session.resume()`（且 workspace 仍可載入）或建立新的 session。

常見 errors：空 ID 的 `INVALID_INPUT`、approval errors、caller origin 無法傳遞時的 `SDK_ORIGIN_UNAVAILABLE`、session 屬於其他 origin 時的 `THREAD_ACCESS_DENIED`、Core 已找不到 ID 時的 `THREAD_NOT_FOUND`，以及 transport errors。

Resume 後要重新註冊 chat、status、error、ended 與 tool handlers。

## `request<T>()`

```ts
request<T>(
  type: string,
  payload?: Record<string, unknown>,
): Promise<T>
```

Low-level bridge request API。

```ts
const result = await pedelec.request<{ sessionId: string }>(
  "create_session",
  {
    input: {
      provider: "codex",
      autoEndOnDisconnect: true,
    },
  },
);
```

:::caution
優先使用 typed public methods。`request<T>()` 不驗證 generic `T` 是否符合 runtime response，low-level operation name/payload 也較容易誤用。
:::

此 method：

- lazy 確保目前存在 Extension port，並在暫時 disconnect 後 retry；
- 套用 `bridgeTimeoutMs`；
- 產生 request ID；
- 經 Extension port post；
- 將 failed bridge response normalize 成 `PedelecError`。

`T` 只存在 compile time。

## Client disconnection

Extension port disconnect 時，已透過該 port 送出的 request 會 reject，registered sessions 收到 SDK error event。Parent client 仍可 reuse，下一個新的 operation 會 reconnect；舊 session handle 不會靜默遷移。若 handle 只是 transport-detached，請呼叫 `resumeSession(sessionId)` 取得新的 handle；若 handle 是明確 `end()` 且仍符合 reactivation 條件，則可在同一個 handle 上呼叫 `session.resume()`。
