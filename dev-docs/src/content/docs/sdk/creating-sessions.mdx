# Creating sessions

The SDK creates a session handle. Choose either Desktop profile mode, where `effortLevel` selects the complete configured profile, or explicit model mode, where `model` and optional provider-native `effort` are snapshotted independently of Desktop profiles.

## Choose a workspace first

The managed convenience path is `pedelec.createSession()`. It creates a managed Workspace automatically, exposes it as `session.workspace`, and does not accept a Workspace option. Use the explicit flow below when the application needs a custom Workspace.

For an application-managed workspace, open the workspace before creating a session. With no path, Pedelec opens the native folder picker and returns `null` when the user cancels:

```ts
const workspace = await pedelec.openWorkspace();
if (!workspace) return;

const session = await workspace.createSession({
  provider: "codex",
  effortLevel: "high",
});
```

An explicit path uses the same validation and initialization flow without opening a picker:

```ts
const workspace = await pedelec.openWorkspace("C:\\workspace\\project-a");
const session = await workspace.createSession({ provider: "codex" });
```

`PedelecWorkspace` exposes `path`, `createSession()`, `listFiles()`, `listFolders()`, and `run()`. See the [PedelecWorkspace reference](../reference/pedelec-workspace/) for method semantics, security, concurrency, and lifetime. A managed session created with `pedelec.createSession()` also exposes its managed Workspace as `session.workspace`; the Workspace handle remains available after `session.end()`.

```ts
const session = await pedelec.createSession();
```

When no input is supplied, SDK reads only `defaultProvider`, validates its availability, and uses effort level `default`.

## Choose an effort level

```ts
const session = await pedelec.createSession({ effortLevel: "high" });
```

This provider-independent form is useful when the application describes intent while the Desktop user owns provider configuration.

## Choose provider, model, and effort

```ts
const session = await pedelec.createSession({
  provider: "codex",
  effortLevel: "low",
});
```

`provider` and `effortLevel` select Desktop profile mode:

```ts
const profileSession = await pedelec.createSession({
  provider: "codex",
  effortLevel: "high",
});
```

Explicit model mode is independent:

```ts
const explicitSession = await pedelec.createSession({
  provider: "codex",
  model: "gpt-x",
  effort: "max",
});
```

`model` is trimmed and used directly. Model-only requests are valid and use provider-default effort behavior. `effort` requires `model`, and explicit mode cannot include `effortLevel`. The SDK and Extension pass the declarative values through, while Core validates provider support and stores the final immutable snapshot. The SDK does not maintain a model catalog; availability, model validity, effort support, and entitlement remain provider-dependent.

For explicit model mode, Core returns `explicitModelConfigApplied: true`. The SDK requires this acknowledgment before uploading Deno Modules or exposing the session; an older Extension/Desktop combination is aborted and reported as incompatible instead of silently using profile semantics.

## Skills

Effort selection composes with skills. Application-owned Workspaces are selected through `openWorkspace()` and then passed implicitly by calling `workspace.createSession()`:

```ts
const session = await pedelec.createSession({
  provider: "claude",
  effortLevel: "default",
  skills: {
    guidance: "Use the declared tools and report structured failures.",
    tools,
  },
});
```

Desktop Settings is the model source only in profile mode. Explicit model mode does not read or merge with a Desktop profile.

## Deno Modules

Configure the Vite plugin once, then declare prepared modules in `skills.denoModules`:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { pedelecVitePlugin } from "@kaoruisaac/pedelec/vite";

export default defineConfig({
  plugins: [pedelecVitePlugin()],
});
```

```ts
import { defineDenoModule } from "@kaoruisaac/pedelec";

const spriteTools = defineDenoModule({
  name: "sprite-tools",
  description: "Sprite authoring and preview utilities.",
  entry: "./agent/sprite-tools.ts",
  usage: `import { previewActorSource } from "sprite-tools";`,
  preferStdinExecution: true,
});

const session = await pedelec.createSession({
  skills: {
    guidance: "Use sprite-tools for sprite authoring tasks.",
    tools: [],
    denoModules: [spriteTools],
  },
});
```

`entry` is resolved by Vite at build/dev time; it is not sent to Desktop. The plugin bundles normal third-party dependencies and generates public declarations. Node built-ins are runtime-provided through Deno's Node compatibility layer: both `node:fs/promises` and legacy bare forms such as `fs/promises` are accepted, and prepared runtime imports use the canonical `node:` form. This does not enable runtime npm, network resolution, or broader filesystem permissions.

The generated `index.d.ts` describes the Agent-facing public API and omits implementation-only dependency types. Module-owned exported types are supported; packages that directly expose dependency-owned or Node-specific external types are not guaranteed to produce a standalone declaration in V1. The Agent imports `sprite-tools` from a script run with `pedelec-deno`; Host Context points exact API questions to `index.d.ts`. Deno Modules are distinct from browser/App Tools in `skills.tools`, which use `pedelec-cli` RPC commands. Session end/resume keeps the same immutable snapshot while Core still knows the thread; create a new session to use a rebuilt artifact.

`preferStdinExecution` is optional. Set it to `true` when a module is primarily used by short scripts; Host Context then supplies that module's stdin `runCommandTemplate`, such as `@'\n<typescript-source>\n'@ | pedelec-deno --thread-id <thread-id> run -`, so the Agent can replace the TypeScript source placeholder and execute the complete stdin command directly. It is an execution preference, not a restriction, so file-backed scripts remain valid. Omit it or set it to `false` for the default behavior. It does not change module bundling or artifact contents.

## Ollama

The selected Ollama profile must contain a model in profile mode, so an empty selected profile returns `MODEL_REQUIRED`. Explicit `createSession({ provider: "ollama", model: "qwen3:30b" })` supplies the model directly and is valid; Ollama currently does not accept explicit `effort`. Low and high do not fall back to default.

## Metadata and resume

Profile-mode sessions expose the normalized `effortLevel` (`default`, `low`, or `high`) on the session and event contexts. Explicit model sessions expose `undefined` because they did not select a Desktop profile. A fresh `resumeSession(sessionId)` handle may not recover provider or effort metadata because the bridge currently returns only the session ID; Core still uses its stored command snapshot.

```ts
session.onChat((_text, context) => {
  console.log(context.provider, context.effortLevel);
});
```

`autoEndOnDisconnect` remains available for lifecycle control. Tool type inference is unchanged.
