# Creating sessions

The SDK creates a session handle. Core resolves the selected provider and Desktop-configured effort profile, then optionally applies a caller-supplied model override before snapshotting the final provider arguments.

## Choose a workspace first

For an application-managed workspace, let the user choose the folder with the native picker before calling `createSession()`:

```ts
const folder = await pedelec.workspaceFolderPicker();
if (!folder) return;

if (!folder.isEmptyFolder && !folder.hasWorkspaceConfig) {
  // The application decides whether to warn the user.
}

const session = await pedelec.createSession({
  workspace: { path: folder.path },
});
```

The picker returns a folder result or `null` on cancellation. It is read-only and reports only the root-folder snapshot (`isEmptyFolder`) and whether `.pedelec-workspace.json` is a regular file (`hasWorkspaceConfig`). It does not decide whether the folder is a valid Pedelec workspace or initialize its contents; Core applies the workspace rules during `createSession()`, then creates the marker after successful custom initialization.

```ts
const session = await pedelec.createSession();
```

When no input is supplied, SDK reads only `defaultProvider`, validates its availability, and uses effort level `default`.

## Choose an effort level

```ts
const session = await pedelec.createSession({ effortLevel: "high" });
```

This provider-independent form is useful when the application describes intent while the Desktop user owns provider configuration.

## Choose provider, model, and effort

```ts
const session = await pedelec.createSession({
  provider: "codex",
  effortLevel: "low",
});
```

`provider` and `effortLevel` are independent of the optional `model` field:

```ts
const session = await pedelec.createSession({
  provider: "codex",
  effortLevel: "high",
  model: "gpt-x",
});
```

An omitted `model` preserves the current behavior. When provided, it is trimmed and replaces only the selected Desktop profile's model; the profile's provider-native effort arguments remain in effect. The SDK and Extension pass the declarative identifier through, while Core performs the provider-specific merge and stores the final immutable snapshot. The SDK does not maintain a model catalog; availability and entitlement remain provider-dependent.

For an explicit model, Core returns an applied acknowledgment. The SDK requires that acknowledgment before uploading Deno Modules or exposing the session; an older Extension/Desktop combination is aborted and reported as incompatible instead of silently dropping the override.

## Skills and workspace

Effort selection composes with skills and an application-owned workspace:

```ts
const session = await pedelec.createSession({
  provider: "claude",
  effortLevel: "default",
  workspace: { path: "C:\\workspace\\project-a" },
  skills: {
    guidance: "Use the declared tools and report structured failures.",
    tools,
  },
});
```

Desktop Settings remains the default source of model selection. Applications may use `model` for a per-session override without replacing the rest of the selected effort profile.

## Deno Modules

Configure the Vite plugin once, then declare prepared modules in `skills.denoModules`:

```ts
// vite.config.ts
import { defineConfig } from "vite";
import { pedelecVitePlugin } from "@kaoruisaac/pedelec/vite";

export default defineConfig({
  plugins: [pedelecVitePlugin()],
});
```

```ts
import { defineDenoModule } from "@kaoruisaac/pedelec";

const spriteTools = defineDenoModule({
  name: "sprite-tools",
  description: "Sprite authoring and preview utilities.",
  entry: "./agent/sprite-tools.ts",
  usage: `import { previewActorSource } from "sprite-tools";`,
  preferStdinExecution: true,
});

const session = await pedelec.createSession({
  skills: {
    guidance: "Use sprite-tools for sprite authoring tasks.",
    tools: [],
    denoModules: [spriteTools],
  },
});
```

`entry` is resolved by Vite at build/dev time; it is not sent to Desktop. The plugin bundles normal third-party dependencies and generates public declarations. Node built-ins are runtime-provided through Deno's Node compatibility layer: both `node:fs/promises` and legacy bare forms such as `fs/promises` are accepted, and prepared runtime imports use the canonical `node:` form. This does not enable runtime npm, network resolution, or broader filesystem permissions.

The generated `index.d.ts` describes the Agent-facing public API and omits implementation-only dependency types. Module-owned exported types are supported; packages that directly expose dependency-owned or Node-specific external types are not guaranteed to produce a standalone declaration in V1. The Agent imports `sprite-tools` from a script run with `pedelec-deno`; Host Context points exact API questions to `index.d.ts`. Deno Modules are distinct from browser/App Tools in `skills.tools`, which use `pedelec-cli` RPC commands. Session end/resume keeps the same immutable snapshot while Core still knows the thread; create a new session to use a rebuilt artifact.

`preferStdinExecution` is optional. Set it to `true` when a module is primarily used by short scripts; Host Context then supplies that module's stdin `runCommandTemplate`, such as `@'\n<typescript-source>\n'@ | pedelec-deno --thread-id <thread-id> run -`, so the Agent can replace the TypeScript source placeholder and execute the complete stdin command directly. It is an execution preference, not a restriction, so file-backed scripts remain valid. Omit it or set it to `false` for the default behavior. It does not change module bundling or artifact contents.

## Ollama

The selected Ollama profile must contain a model unless an explicit `model` override is supplied. An empty selected profile therefore returns `MODEL_REQUIRED` without an override, while `createSession({ provider: "ollama", effortLevel: "low", model: "qwen3:30b" })` is valid. Low and high do not fall back to default.

## Metadata and resume

New sessions expose the normalized `effortLevel` (`default`, `low`, or `high`) on the session and event contexts. A fresh `resumeSession(sessionId)` handle may not recover provider or effort metadata because the bridge currently returns only the session ID; Core still uses its stored command snapshot.

```ts
session.onChat((_text, context) => {
  console.log(context.provider, context.effortLevel);
});
```

`autoEndOnDisconnect` remains available for lifecycle control. Tool type inference is unchanged.
