All types below are exported from `@kaoruisaac/pedelec`.

```ts
import type {
  PedelecOptions,
  ProviderCode,
  EffortLevel,
  Effort,
  ProviderInfo,
  PedelecSessionStatus,
  PedelecSessionUsage,
  ToolArgsSchema,
  Asset,
  AssetPath,
  ReadAssetType,
  PedelecWorkspace,
  WorkspaceRunOptions,
  WorkspaceRunResult,
} from "@kaoruisaac/pedelec";
```

## Client and session input

### `PedelecOptions`

```ts
type PedelecOptions = {
  bridgeTimeoutMs?: number;
};
```

### `ProviderCode`

```ts
type ProviderCode =
  | "codex"
  | "antigravity"
  | "opencode"
  | "cursor"
  | "claude"
  | "ollama";
```

### `EffortLevel`

```ts
type EffortLevel = "default" | "low" | "high";
```

`EffortLevel` is the Pedelec/Desktop profile selector. It selects one complete configured profile, including that profile's model and provider-native effort settings.

### `Effort`

```ts
type Effort = "low" | "medium" | "high" | "xhigh" | "max";
```

`Effort` is the provider-native reasoning-effort value used only in explicit model mode. It is optional when `model` is supplied and cannot be used by itself. Provider-specific support is validated at runtime.

### `CreateSessionInput`

```ts
type CreateSessionInput<
  TTools extends readonly ToolDefinition[] = readonly ToolDefinition[],
> =
  | {
      provider?: ProviderCode;
      effortLevel?: EffortLevel;
      model?: never;
      effort?: never;
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    }
  | {
      provider?: ProviderCode;
      model: string;
      effort?: Effort;
      effortLevel?: never;
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    };
```

`effortLevel` selects Desktop profile mode. `model` selects explicit provider configuration and may be paired with provider-native `effort`; these modes are mutually exclusive. Model-only explicit mode is valid and uses provider-default effort behavior. `effort` cannot be supplied without `model`.

### `PedelecWorkspace`

```ts
class PedelecWorkspace {
  readonly path: string | null;
  createSession(): Promise<PedelecSession<string>>;
  createSession<const TTools extends readonly ToolDefinition[]>(
    input: CreateSessionInput<TTools>,
  ): Promise<PedelecSession<ToolNameOf<TTools>>>;
  listFiles(path?: string): Promise<string[]>;
  listFolders(path?: string): Promise<string[]>;
  run(script: string, options?: WorkspaceRunOptions): Promise<WorkspaceRunResult>;
}
```

`PedelecWorkspace` is returned by `openWorkspace()`, `createSession().workspace`, and `resumeSession().workspace`. Its opaque workspace identity is intentionally not public.

### `ProviderInfo`

```ts
type ProviderInfo = {
  name: string;
  code: ProviderCode;
  available: boolean;
  isDefault: boolean;
  error: string | null;
};
```

### `PedelecSettings`

```ts
type PedelecSettings = {
  defaultProvider: ProviderCode | null;
};
```

### `ApprovalStatus`

```ts
type ApprovalStatus = {
  installed: boolean;
  approved: boolean;
  origin: string | null;
  appConnected: boolean;
};
```

### `PedelecAvailability`

```ts
type PedelecAvailability = {
  available: boolean;
  extension: { available: boolean };
  approval: { approved: boolean; origin: string | null };
  desktop: { available: boolean; launchAttempted: boolean };
  error?: PedelecError;
};
```

`PedelecSettings` is a public defaults-only DTO: it never contains provider credentials. `ProviderInfo` only exposes `name`, `code`, `available`, `isDefault`, and `error`. `isDefault` reflects the current Desktop default provider and is independent of `available`.

`available` requires every layer. `launchAttempted` can be true once the non-sensitive approval-status ping is sent; it does not confirm a process launch. `appConnected` reflects that ping only, not approval or provider readiness.

## Assets

### `AssetPath`

```ts
type AssetPath = `/${string}`;
```

The SDK public path for an asset in the Workspace shared store. Physically, the Agent-visible shared store is `<workspace.path>/.pedelec-runtime/assets/`; the `.pedelec-runtime` directory is private runtime layout and is not exposed in SDK values. For example, `/images/photo.png` refers to `<workspace.path>/.pedelec-runtime/assets/images/photo.png`. Runtime validation also rejects backslashes, empty path segments, `.` and `..`.

### `ReadAssetType`

```ts
type ReadAssetType = "text" | "json" | "file";
```

Selects the conversion performed by `PedelecSession.readAsset()`: strict UTF-8 text, parsed JSON, or a browser `File`.

### `Asset`

```ts
type Asset = {
  name: string;
  path: AssetPath;
  sizeBytes: number;
  modifiedAt: number;
};
```

`modifiedAt` is the workspace filesystem modification time. `path` is workspace-relative and does not reveal the browser user's absolute local path.

## Errors and status

### `PedelecError`

```ts
type PedelecError = {
  code: string;
  message: string;
  details?: unknown;
};
```

Do not assume `details` has one global shape. Narrow by `code` and validate before reading.

### `PedelecSessionStatus`

```ts
type PedelecSessionStatus =
  | "idle"
  | "running"
  | "waiting_tool_result"
  | "ended"
  | "error";
```

### `PedelecSessionUsage`

```ts
type PedelecSessionUsage = {
  totalTokens?: number;
};
```

`totalTokens` is the normalized cumulative token total observed for one session. It is omitted until a supported provider reports a valid value.

## JSON value types

### `JsonPrimitive`

```ts
type JsonPrimitive = string | number | boolean | null;
```

### `JsonValue`

```ts
type JsonValue =
  | JsonPrimitive
  | JsonValue[]
```

## Tool definitions

### `ToolSpecificHandler`

```ts
type ToolSpecificHandler<TArgs = unknown, TResult = unknown> = (
  args: TArgs,
  ctx: ToolCallContext,
) => TResult | Promise<TResult>;
```

### `ToolDefinition`

```ts
type ToolDefinition<
  TArgs = unknown,
  TResult = unknown,
  TName extends string = string,
> = {
  name: TName;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
  handler?: ToolSpecificHandler<TArgs, TResult>;
};
```

### `DenoModuleDefinition`

```ts
type DenoModuleDefinition<TName extends string = string> = {
  name: TName;
  description: string;
  entry: string;
  usage: string;
  preferStdinExecution?: boolean;
};
```

`entry` is a Vite build/dev authoring string. `name` becomes the Agent import specifier and `usage` is required guidance for the common import. `preferStdinExecution` is an optional Agent execution preference; when `true`, Host Context supplies a module-specific stdin `runCommandTemplate` with a `<typescript-source>` placeholder. File-backed execution remains valid, and the preference does not change bundling or artifact contents. Use `pedelecVitePlugin()` to prepare the runtime and declaration artifact.

### `SkillsInput`

```ts
type SkillsInput<
  TTools extends readonly ToolDefinition[] = readonly ToolDefinition[],
> = {
  guidance: string;
  tools: TTools;
  denoModules?: readonly DenoModuleDefinition[];
};
```

### `ToolNameOf`

```ts
type ToolNameOf<TTools extends readonly ToolDefinition[]> = Extract<
  TTools[number]["name"],
  string
>;
```

### Serializable manifests

```ts
type SerializableToolManifest = {
  name: string;
  description: string;
  argsSchema: ToolArgsSchema;
  timeoutMs?: number;
};

type SerializableSkillsManifest = {
  guidance: string;
  tools: SerializableToolManifest[];
  denoModules?: Array<{
    name: string;
    description: string;
    usage: string;
    preferStdinExecution?: boolean;
  }>;
};
```

Inline handlers and the build-time `entry` field are not part of the serialized manifest.

## Tool schema metadata

```ts
type ToolArgsSchemaMeta<
  TDefault extends JsonValue = JsonValue,
> = {
  description?: string;
  default?: TDefault;
  examples?: TDefault[];
};
```

### Boolean


### Array

```ts
type ToolArgsArraySchema = ToolArgsSchemaMeta<JsonValue[]> & {
  type: "array";
  items: ToolArgsSchemaNode;
  minItems?: number;
  maxItems?: number;
  uniqueItems?: boolean;

```

### Object

```ts
type ToolArgsObjectSchema = ToolArgsSchemaMeta<
  Record<string, JsonValue>
> & {
  type: "object";
  properties?: Record<string, ToolArgsSchemaNode>;
  required?: string[];
};
```

### One-of

```ts
type ToolArgsOneOfSchema = ToolArgsSchemaMeta & {
  oneOf: ToolArgsSchemaNode[];
};
```

### Node and root aliases

```ts
type ToolArgsSchemaNode =
  | ToolArgsStringSchema
  | ToolArgsNumberSchema
  | ToolArgsIntegerSchema
  | ToolArgsBooleanSchema
  | ToolArgsArraySchema
  | ToolArgsObjectSchema
  | ToolArgsOneOfSchema;

type ToolArgsSchema = ToolArgsObjectSchema;
```

The root alias enforces an object schema at compile time.
