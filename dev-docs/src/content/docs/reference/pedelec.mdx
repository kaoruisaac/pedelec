`Pedelec` is the browser client that owns the Chrome Extension bridge and creates or resumes `PedelecSession` objects.

```ts
import { Pedelec } from "@kaoruisaac/pedelec";
```

## Constructor

```ts
new Pedelec(options?: PedelecOptions)
```

```ts
type PedelecOptions = {
  bridgeTimeoutMs?: number;
};
```

### Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `options.bridgeTimeoutMs` | `number` | `30_000` | Maximum wait for an Extension bridge response. Values below 1 are clamped to 1. |

The constructor attempts to connect to the Pedelec Chrome Extension immediately. Construct it only in a browser page after hydration.

```ts
const pedelec = new Pedelec({
  bridgeTimeoutMs: 30_000,
});
```

## `createSession()`

```ts
createSession(): Promise<PedelecSession<string>>;

createSession<const TTools extends readonly ToolDefinition[]>(
  input: CreateSessionInput<TTools>,
): Promise<PedelecSession<ToolNameOf<TTools>>>;
```

Creates a new Core session and subscribes the current SDK channel to it.

### Input

```ts
type CreateSessionInput<TTools extends readonly ToolDefinition[]> =
  | {
      provider: ProviderCode;
      model?: string;
      effortLevel?: "default" | "low" | "high";
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    }
  | {
      provider?: undefined;
      model?: string;
      effortLevel?: "default" | "low" | "high";
      skills?: SkillsInput<TTools>;
      autoEndOnDisconnect?: boolean;
    };
```

### Resolution rules

- No `provider`: use Desktop `defaultProvider`; verify it is available.
- `provider` may be combined with provider-independent `effortLevel` in Desktop profile mode.
- Explicit model mode uses `model` with optional provider-native `effort`; it must not include `effortLevel`.
- Model-only explicit mode uses provider-default effort behavior. Omitted `effortLevel` is normalized to `default` only in profile mode.
- `autoEndOnDisconnect`: defaults to `true`.

`createSession()` always uses the managed convenience flow and does not accept Workspace configuration. For an application-managed Workspace, call `openWorkspace()` and then `workspace.createSession()`. See the [PedelecWorkspace reference](../pedelec-workspace/) for the Workspace methods, lifecycle, concurrency, and security boundary.

### Returns

A `PedelecSession` registered in this client.

### Common errors

- approval and transport errors;
- `DEFAULT_PROVIDER_NOT_SET`;
- `DEFAULT_PROVIDER_UNAVAILABLE`;
- `INVALID_INPUT`;
- `MODEL_REQUIRED` when profile-mode Ollama has no model in the selected effort profile;
- provider/Core creation errors.

### Example

```ts
const session = await pedelec.createSession({
  provider: "codex",
  autoEndOnDisconnect: true,
});
```

## `openWorkspace()`

```ts
openWorkspace(): Promise<PedelecWorkspace | null>
openWorkspace(path: string): Promise<PedelecWorkspace>
```

Opens or initializes a workspace capability. Without a path, Pedelec Desktop opens the native directory picker and cancellation resolves to `null`. An explicit path bypasses the picker. The returned workspace exposes `path`, `createSession()`, `listFiles()`, `listFolders()`, and `run()`.

```ts
const workspace = await pedelec.openWorkspace();
if (!workspace) return;

const session = await workspace.createSession({ provider: "codex" });
const files = await workspace.listFiles();
const result = await workspace.run("console.log('hello');");
```

This is a sensitive Desktop API and may trigger the current origin's approval flow. Workspace validation, runtime initialization, and marker handling are performed by Core. The picker overload has no generic SDK bridge timeout while the native picker is open; the explicit-path overload uses the configured bridge timeout. Extension disconnects and explicit bridge errors still reject.

## `listProviders()`

```ts
listProviders(): Promise<ProviderInfo[]>
```

Returns provider discovery results from Desktop Core.

```ts
type ProviderInfo = {
  name: string;
  code: ProviderCode;
  available: boolean;
  isDefault: boolean;
  error: string | null;
};
```

```ts
const providers = await pedelec.listProviders();
const ready = providers.filter((provider) => provider.available);
```

`isDefault` identifies the provider selected by the current Desktop settings. It is independent of `available`, so it remains true when the selected provider is unavailable. `available` is a discovery/setup signal, not a guarantee that every model or remote service is ready. The SDK ignores unknown fields added to Extension responses for forward compatibility.

### Common errors

Extension, native host, Core IPC, and bridge timeout errors.

## `getSettings()`

```ts
getSettings(): Promise<PedelecSettings>
```

Reads the SDK-visible Desktop defaults.

```ts
type PedelecSettings = {
  defaultProvider: ProviderCode | null;
};
```

The SDK validates the returned shape. An incompatible response rejects with `SDK_PROTOCOL_ERROR`.

```ts
const settings = await pedelec.getSettings();
console.log(settings.defaultProvider);
```

## `getApprovalStatus()`

```ts
getApprovalStatus(): Promise<ApprovalStatus>
```

```ts
type ApprovalStatus = {
  installed: boolean;
  approved: boolean;
  origin: string | null;
  appConnected: boolean;
};
```

Reads the current origin's Extension approval state.

Special behavior: when the Extension is unavailable or disconnected, this method resolves instead of throwing:

```ts
{
  installed: false,
  approved: false,
  origin: location.origin,
  appConnected: false
}
```

Other errors, such as protocol/storage failures, may reject.

Calling this method does not open the approval popup. `createSession()` or `resumeSession()` triggers approval when required.

## `checkAvailability()`

```ts
checkAvailability(): Promise<PedelecAvailability>
```

Checks Extension reachability, current-origin approval, and (only after approval) Desktop readiness. It does not create or resume a session and never opens the approval popup.

```ts
const availability = await pedelec.checkAvailability();
if (availability.available) {
  // Extension, approval, and Desktop settings probe all succeeded.
}
```

`getSettings()` and `listProviders()` require origin approval and can trigger its popup. They expose only public defaults and `name`/`code`/`available`/`isDefault`/`error` respectively. `getApprovalStatus().appConnected` is the non-sensitive Core ping result for connectivity; it does not imply approval or provider readiness.

It resolves structured unavailable states for bridge, Native Host, Core, timeout, and settings-protocol failures. `launchAttempted: true` means a status ping or settings probe was sent and may have invoked auto-launch; it does not prove Desktop was launched.

## `resumeSession()`

```ts
resumeSession(sessionId: string): Promise<PedelecSession<string>>
```

Subscribes this SDK client to an existing Core session and hydrates its associated `workspace`. This is a reattachment operation, not ended-thread reactivation: if Core reports `ended`, the returned handle remains ended. The returned Session already includes `session.workspace`; the application does not need to call `openWorkspace()` separately.

```ts
const session = await pedelec.resumeSession(savedSessionId);
```

### Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `sessionId` | `string` | Non-empty Core session/thread identifier. |

### Returns

A session handle registered in this client. A newly resumed handle may not contain provider/effort metadata because the current bridge response returns only the ID.

### Common errors

- `INVALID_INPUT` for an empty ID;
- approval errors;
- `SDK_ORIGIN_UNAVAILABLE` when the caller origin cannot be forwarded;
- `THREAD_ACCESS_DENIED` when the session belongs to another origin;
- `THREAD_NOT_FOUND` when Core no longer knows the ID; and
- transport errors.

After resume, register chat, status, error, ended, and tool handlers again.

## `request<T>()`

```ts
request<T>(
  type: string,
  payload?: Record<string, unknown>,
): Promise<T>
```

Low-level bridge request API.

```ts
const result = await pedelec.request<{ sessionId: string }>(
  "create_session",
  {
    input: {
      provider: "codex",
      autoEndOnDisconnect: true,
    },
  },
);
```

:::caution
Prefer typed public methods. `request<T>()` does not validate that your generic `T` matches the runtime response, and low-level operation names/payloads are easier to misuse.
:::

The method:

- lazily ensures that a current Extension port exists, retrying after a transient disconnect;
- applies `bridgeTimeoutMs`;
- generates a request ID;
- posts through the Extension port; and
- normalizes failed bridge responses as `PedelecError`.

`T` is compile-time only.

## Client disconnection

When the Extension port disconnects, requests already sent through that port reject and registered sessions receive an SDK error event. The parent client remains reusable and reconnects on the next new operation; old session handles do not silently migrate. A transport-detached old handle cannot call `session.resume()`; resume an intentional surviving session with `resumeSession(sessionId)`.
